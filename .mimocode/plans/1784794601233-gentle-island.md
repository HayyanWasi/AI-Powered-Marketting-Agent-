## 1. Executive Summary

### What is this project?
An AI-powered marketing campaign automation platform for a single organization that runs educational events (seminars, workshops, hackathons, entry tests). A non-marketing user enters event details, optionally uploads images, and the system automatically generates a complete marketing campaign: captions, hashtags, and poster images.

### What problem does it solve?
Eliminates the need for a marketing team by automating social media content creation for educational events.

### Who uses it?
- Non-technical event organizers who need marketing materials
- Single-organization deployment (not multi-tenant SaaS)

### Overall Architecture
```
Frontend (Next.js 15) ──REST──▶ Backend (FastAPI) ──▶ Agents Pipeline
                                    │                       │
                                    ├── Supabase (DB)       ├── Groq (LLM primary)
                                    ├── Cloudflare (Images) ├── Gemini (LLM fallback)
                                    └── DuckDuckGo (Search) └── Cloudflare (Image gen)
```

### Technologies
| Layer | Technology |
|-------|-----------|
| Frontend | Next.js 15, React 19, TypeScript, Tailwind CSS |
| Backend | Python 3.13, FastAPI, Pydantic v2 |
| Database | Supabase PostgreSQL |
| Storage | Supabase Storage (brand images) |
| LLM | Groq (Llama 3.3 70B) primary, Gemini 2.5 Flash fallback |
| Image Gen | Cloudflare Workers AI (FLUX text2img, SD img2img) |
| Search | DuckDuckGo |
| Auth | Placeholder (hardcoded UUID) |

### Current Maturity Level: **Early Prototype (35%)**
- Core pipeline works end-to-end
- Authentication is stubbed
- No real deployment infrastructure
- No poster assembly
- No social media scheduling
- Many v1 API wrappers are stubs

### Biggest Strengths
1. Clean agent pipeline with immutable context pattern
2. Dual LLM fallback (Groq → Gemini) with auth error detection
3. Comprehensive test suite (670+ tests, 42% coverage)
4. Well-structured Pydantic models and validation
5. Good separation of concerns in the agent layer

### Biggest Weaknesses
1. Two competing API entry points (main.py routes vs api.py factory)
2. Orphaned modules (modules/ai_generation, workflow_engine, operations)
3. Authentication completely stubbed
4. v1 API wrappers are mostly stubs returning hardcoded data
5. Incomplete frontend-backend integration

### 3.1 Agent Pipeline (`backend/src/agents/`)

**Purpose:** Modular pipeline where each agent performs a single task and passes immutable context to the next.

**Pipeline Flow:**
```
ContextBuilder (reads DB + search)
    ↓
GenerationContext (immutable snapshot)
    ↓
Orchestrator.execute():
  1. ReferenceMatcherAgent   → validates brand data exists
  2. StrategyAgent           → calls LLM for strategy brief
  3. CampaignPlannerAgent    → generates calendar slots
  4. ContentGenerationAgent  → calls LLM for copy (per slot)
  5. HashtagResearchAgent    → searches DuckDuckGo for hashtags
  6. HookAnalyzerAgent       → scores hooks 0-100
```

## 4. Execution Flow

### Campaign Generation (End-to-End)

```
1. User clicks "Generate" in frontend
   │
2. Frontend: workflowService.execute() → POST /api/workflow/execute
   │
3. Backend: routes/workflow.py → _execute_campaign_generation()
   │
4. ContextBuilder.build():
   ├── Load company profile from Supabase (company_profiles table)
   ├── Search DuckDuckGo for each guest name
   ├── Create immutable GenerationContext snapshot
   │
5. Orchestrator.execute():
   ├── ReferenceMatcherAgent → validates brand exists
   ├── StrategyAgent → calls Groq/Gemini LLM for strategy
   ├── CampaignPlannerAgent → generates calendar slots (date math)
   ├── ContentGenerationAgent → calls LLM per slot (3 variants + image prompt)
   ├── HashtagResearchAgent → searches DuckDuckGo for hashtags
   ├── HookAnalyzerAgent → scores hooks 0-100
   ├── ReadabilityScorerAgent → scores readability 0-100
   ├── ValidationAgent → checks limits, scores, images
   └── AssetGenerationAgent → generates images via Cloudflare
   │
6. Result returned to frontend
   │
7. Frontend: Polls workflow status, displays on /review page
```

### Guest Search Flow

```
1. Frontend: companyService.searchGuest() → POST /api/guest/search
   │
2. Backend: GuestSearchService.search() → DuckDuckGo API
   │
3. LLMService.generate() → Groq/Gemini with analysis prompt
   │
4. Parse JSON response → GuestProfile
   │
5. Upsert to guest_profiles table
   │
6. Return profile to frontend
```

### Image Generation Flow (Agent Pipeline)

```
1. AssetGenerationAgent.execute()
   │
2. For each ContentDraft:
   ├── Build image prompt from draft + brand context
   ├── If reference images exist:
   │   ├── Download reference image
   │   └── CloudflareImageService.generate_from_reference() (img2img)
   ├── Else:
   │   └── CloudflareImageService.generate_from_text() (text2img)
   └── Convert bytes → base64 data URL
```

### Image Generation Flow (Route)

```
1. POST /api/campaign-images
   │
2. Try CloudflareImageService first:
   ├── If reference image: generate_from_reference()
   └── Else: generate_from_text()
   │
3. Upload to Supabase Storage
   │
4. If Cloudflare fails → fallback to PollinationsService
   │
5. Return public URL
```

## 10. Rendering Pipeline

**Note:** There is no rendering pipeline in this project. The project generates marketing copy and images, not rendered documents/posters.

**Image Generation Pipeline:**
```
ContentGenerationAgent (LLM) → IMAGE_PROMPT per slot
        ↓
AssetGenerationAgent:
  ├── If reference images exist:
  │   ├── Download reference image bytes
  │   └── CloudflareImageService.generate_from_reference(prompt, ref_bytes)
  │       → POST to SD img2img → raw PNG bytes
  └── Else:
      └── CloudflareImageService.generate_from_text(prompt)
          → POST to FLUX schnell → base64 JSON → decode
        ↓
Convert bytes → base64 data URL
        ↓
ValidationAgent:
  ├── Decode base64 → Pillow
  ├── Check dimensions (min 1080x1080)
  └── Check file size
```

**Campaign Images Route Pipeline:**
```
POST /api/campaign-images
  ├── Try Cloudflare first (img2img or text2img)
  ├── Upload bytes to Supabase Storage
  ├── If Cloudflare fails → fallback to Pollinations URL
  └── Return public URL
```

## 12. Service Documentation

### LLM Service (`services/llm_service.py`)
- **Responsibilities:** LLM inference with Groq primary, Gemini fallback
- **Inputs:** LLMRequest (system_prompt, user_prompt, template_name, template_variables)
- **Outputs:** LLMResponse (text, token_usage, provider, model)
- **Dependencies:** settings, prompts, openai SDK (for Groq), google-generativeai
- **Side effects:** HTTP calls to Groq/Gemini APIs; retry with backoff
- **Reuse:** Used by strategy agent, content generator, guest route

### Cloudflare Image Service (`services/cloudflare_image_service.py`)
- **Responsibilities:** Image generation via Cloudflare Workers AI
- **Inputs:** prompt (str), reference_image_bytes (optional)
- **Outputs:** image bytes (PNG)
- **Dependencies:** settings, httpx
- **Side effects:** HTTP calls to Cloudflare API; retry on 429/5xx
- **Reuse:** Used by asset generator, campaign images route

### Search Service (`services/search.py`)
- **Responsibilities:** DuckDuckGo web search with rate limiting
- **Inputs:** guest_name (str), company_name (optional str)

## 16. Error Handling Review

### Current Error Handling
- Global exception handlers in `exception_handlers.py` map domain errors to HTTP responses
- Services raise domain-specific exceptions (NotFoundError, StateTransitionError, etc.)
- Agents return AgentResult with success/failure + message
- LLM failures fall back to placeholder content

### Missing Validation
- No input sanitization on search queries
- No rate limiting on workflow execution
- No file size limits on workflow input

### Silent Failures
- `ReferenceMatcherAgent` returns success even when brand data is empty (logs warning)
- `CampaignPlannerAgent` skips slots without platforms silently
- `AssetGenerationAgent` leaves image fields empty on failure (graceful degradation)

### Recovery Strategy
- LLM failures → fallback to placeholder content
- Image generation failures → empty image (validation catches this)
- Search failures → skip guest (context continues with fewer guests)
- DB failures → graceful degradation (empty brand data)

### Weaknesses
- `traceback.print_exc()` used instead of logging in `general_exception_handler`
- No circuit breaker pattern for external services
- No retry coordination between services

### Architectural Blockers for Scaling

4. No task queue for long-running generation
5. Module-level service instantiation (can't swap per-request)

## 21. New Developer Guide

### Project Purpose
Automate marketing campaign creation for educational events using AI.

### Main Folders
1. `backend/src/agents/` — The core AI pipeline
2. `backend/src/services/` — Business logic
3. `backend/src/api/routes/` — HTTP endpoints
4. `frontend/src/app/` — User interface

### Execution Flow
1. User enters event details in frontend
2. Frontend calls `/api/workflow/execute`
3. Backend builds context from DB + search
4. Pipeline runs 9 agents sequentially
5. Results returned to frontend for review

### Important Modules
- `agents/orchestrator.py` — Pipeline coordinator
- `agents/context.py` — Shared data structure
- `services/llm_service.py` — LLM inference
- `services/cloudflare_image_service.py` — Image generation

### Things to Avoid
- Don't add routes to both `main.py` and `api.py`
- Don't modify `modules/` (it's orphaned)
- Don't use `settings.openai_api_key` (doesn't exist)
- Don't assume authentication works (it's stubbed)

### Where to Start
1. Read `agents/context.py` (data model)
2. Read `agents/orchestrator.py` (pipeline)
3. Read `services/llm_service.py` (LLM integration)
4. Read `api/routes/workflow.py` (API entry point)

### How to Safely Add Features
1. Add new agent in `agents/` inheriting `BaseAgent`
2. Register in `orchestrator.py`
3. Add route in `api/routes/`
4. Add wrapper in `api/v1/`
5. Write tests

### Common Mistakes
- Using `asyncio.run()` in sync code (use carefully)
- Not using `dataclasses.replace()` for context updates
- Hardcoding service instantiation instead of DI

### Reading Order
1. `agents/context.py` → `agents/base.py` → `agents/orchestrator.py`
2. `services/llm_service.py` → `services/cloudflare_image_service.py`
3. `api/routes/workflow.py` → `api/api.py`
4. `config/settings.py` → `config/prompts.py`
